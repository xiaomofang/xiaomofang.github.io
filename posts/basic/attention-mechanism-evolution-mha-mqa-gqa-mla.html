注意力机制如何演变：从 MHA 到 MQA、GQA 与 MLA

MHA、MQA、GQA、MLA 不是四个互不相干的缩写，而是同一个问题的四次重新参数化：在不让 query 的多头表达能力消失的前提下，怎样减少每个 token 必须携带、读取和通信的 Key/Value 状态。本文以原论文为主线，解释每一步为什么出现，以及它换来了什么、又牺牲了什么。

Attention 加速 硬件与 Kernel

2026年9月5日 · 24 分钟 · 0 字 · MOFANG

先把结论放在桌面上：训练时，Q/K/V 的计算量都重要；自回归推理时，历史 K/V 的存储和搬运往往更先成为瓶颈。 因而演变方向不是简单地“减少 head”，而是把共享发生在不同层次：MHA 不共享，MQA 全共享，GQA 分组共享，MLA 则进一步把历史状态压缩成低维 latent。

1MHA

每个 query head 都有独立 K/V，表达最完整。

→
2MQA

所有 query head 共享一组 K/V，KV cache 最小。

→
3GQA

把极端共享改成分组共享，恢复质量与带宽的平衡。

→
4MLA

不只共享 head，而是压缩历史 KV 的表示。

一、统一坐标：注意力究竟在缓存什么

1.1 从 scaled dot-product attention 开始

给定 query、key、value，单个 head 的注意力是：

\[ \operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}\right)V \]

在 decoder 的第 \(t\) 步，当前 query 只对应一个新 token，但它要和位置 \(1\) 到 \(t\) 的所有 key 做匹配。因此历史 \(K_{1:t}\) 和 \(V_{1:t}\) 会被放入 KV cache。若 batch 为 \(B\)、层数为 \(L\)、KV head 数为 \(H_{kv}\)、每个 head 维度为 \(d\)，半精度 KV cache 的近似字节数是：

\[ \operatorname{KVBytes}\approx 2\times B\times L\times T\times H_{kv}\times d\times 2 \]

第一个 2 是 K 与 V，第二个 2 是 FP16 每元素字节数。这个式子直接揭示了优化入口：在模型宽度和上下文长度不变时，把 \(H_{kv}\) 从 query head 数降下来，cache 和每步读取量就近似线性下降。

不要混淆两个 head 数。 Query head 数 \(H_q\) 决定当前 token 有多少种独立的匹配视角；KV head 数 \(H_{kv}\) 决定历史状态复制多少份。MHA 中二者相等，MQA 中 \(H_{kv}=1\)，GQA 位于二者之间。

1.2 一个可手算的 cache 例子

假设单层、batch=1、上下文 \(T=4096\)、head 维度 \(d=128\)，比较 32 个 query heads 的三种布局。MHA 有 32 个 KV heads，MQA 有 1 个，GQA-8 有 8 个：

布局KV heads单层 KV 元素相对 MHA
MHA322 × 4096 × 32 × 128 = 33,554,4321×

这只是一个 layer、一个 batch；乘上几十层和并发请求后，差距会直接进入显存容量、KV 传输和可容纳 batch 的计算。代价也同样清楚：共享越激进，所有 query head 能读取的历史内容越相似。

二、MHA：表达能力的基准答案

2.1 Multi-Head Attention 的结构

Transformer 论文将输入分别投影到多个子空间，每个 head 独立形成 \(Q_i,K_i,V_i\)，最后拼接并线性投影：

\[ \operatorname{MultiHead}(Q,K,V)=\operatorname{Concat}(head_1,\ldots,head_h)W^O,\quad head_i=\operatorname{Attention}(QW_i^Q,KW_i^K,VW_i^V) \]

MHA 的关键不是“有很多头”这件事本身，而是每个头拥有自己的 K/V 投影。某个头可以专注于局部位置、句法依赖或长距离指代，另一个头可以学习完全不同的相似度几何。训练阶段，这种独立性通常是最宽松的上限。

MHA 的隐性账单：在 decoder 推理中，独立的 K/V 会随序列长度累积。它并不只占显存，还会在每个 token 生成时被反复从 HBM 读出，成为典型的 memory-bandwidth 问题。

三、MQA：保留多头 query，所有 head 共用历史

3.1 Shazeer 的极端共享

MQA（Multi-Query Attention）的做法很直接：保留 \(H_q\) 个 query heads，但只使用一组 K/V。写成形状就是：

\[ Q\in\mathbb{R}^{T\times H_q\times d},\qquad K,V\in\mathbb{R}^{T\times 1\times d} \]

广播后的同一组 K/V 会被每个 query head 使用。于是不同 head 仍可通过不同的 \(W_i^Q\) 产生不同查询，却不能再通过独立的 key/value 表示保存不同历史视角。Shazeer 的论文报告了生成时的显著加速，根因正是把增量解码的内存带宽压力降了下来，而不是让矩阵乘法突然少了同样比例。

3.2 为什么 MQA 不是免费午餐

如果一个 query head 学到“看句法”，另一个学到“看实体”，MHA 允许它们分别定义 key/value 空间；MQA 要求它们从同一份历史表示中取材。于是 MQA 的收益与风险是一一对应的：KV cache 从 \(H_q\) 份变成 1 份，但 head 之间的历史记忆容量也被压到一份。

工程上常见的做法是从 MHA checkpoint 迁移：把多个 K/V head 平均或复制成一组，再进行少量 uptraining。这个过程不是数学上等价的重参数化，而是用额外训练把性能损失补回来。

四、GQA：把二元选择变成连续旋钮

4.1 分组共享

GQA（Grouped-Query Attention）观察到 MHA 和 MQA 之间并非只有两个点。将 \(H_q\) 个 query heads 分成若干组，每组共享一个 K/V head：

\[ H_q = G\times r,\qquad H_{kv}=G,\qquad K_i=K_{\lfloor i/r\rfloor},\;V_i=V_{\lfloor i/r\rfloor} \]

其中 \(1\le G=H_{kv}\le H_q\) 时，\(G=H_q\) 退化为 MHA，\(G=1\) 退化为 MQA。通常要求每组 query head 数 \(r=H_q/G\) 为整数。这样模型设计者有了一个可调旋钮：用更多 KV heads 买回表达能力，用更少 KV heads 换取 cache 和带宽。

4.2 GQA 的迁移为何比 MQA 更稳

从 MHA checkpoint 转成 GQA 时，只需把若干相邻或按规则选出的 K/V head 聚合成一组；每个 query head 仍保留自己的投影。分组数越大，丢掉的 K/V 子空间越少；分组数越小，解码读取越省。GQA 论文的贡献不只是提出结构，还给出从 MHA checkpoint 出发的 uptraining 路径，使实际模型不用从随机初始化重新学习。

GQA 的本质：它没有改变 attention 的公式，也没有减少 query head 的数量；它改变的是 K/V 的“复用拓扑”。因此它通常是现有 MHA 模型走向高并发推理时最容易落地的折中。

五、MLA：从共享 head 到压缩历史状态

5.1 latent KV 的想法

MLA（Multi-head Latent Attention）来自 DeepSeek-V2。它不满足于选择多少个 KV head，而是把 K/V 的历史信息压到一个低维 latent 向量 \(c_t^{KV}\)，推理时缓存 latent，而不是缓存每个 head 的完整 K/V：

\[ c_t^{KV}=W^{DKV}h_t,\qquad k_t^C=W^{UK}c_t^{KV},\qquad v_t^C=W^{UV}c_t^{KV} \]

这里 \(W^{DKV}\) 是下投影，\(W^{UK},W^{UV}\) 是上投影。关键空间复杂度从“每个 token 存所有 KV head”变成“每个 token 存一个共享的低维 code”。在 RoPE 存在时，MLA 还需要仔细处理位置编码：论文将可吸收的内容部分与解耦的 RoPE 部分分开，使压缩后的表示仍能表达相对位置关系。

5.2 MLA 与 GQA 的区别

GQA 仍然在“完整 K/V head 的复制份数”上做文章：一组 head 共享一个 K/V。MLA 则改变缓存对象本身：历史不以展开后的 K/V 保存，而以 latent 保存，再通过投影参与注意力。前者是结构化共享，后者是低秩压缩；二者都减少通信，却不是同一个等价变换。

这也解释了 MLA 的实现复杂度：它需要选择 latent 维度、处理 Q/K 的吸收与重排、兼容 RoPE，并让 kernel 避免把压缩状态无谓地展开回完整 KV。换句话说，MLA 把一部分 KV cache 问题转换成了投影、布局和 kernel 融合问题。

六、把演变放回推理系统

6.1 Prefill 与 decode 看到的不是同一个瓶颈

Prefill 可以把一段序列组成大矩阵，矩阵乘法的算术强度较高；decode 每次通常只新增一个 query，却要扫描越来越长的历史 KV，因而更容易受带宽和 cache 读取限制。MHA → MQA/GQA/MLA 的收益主要发生在后者。它们不会神奇地让所有 attention FLOPs 消失，也不会自动解决通信、调度和 kernel launch。

6.2 选择机制的实际准则

场景优先考虑理由
追求模型质量上限、训练新模型MHA 或较大的 GQA保留更多独立 K/V 子空间，风险最小。
已有 MHA checkpoint、希望快速降低 cacheGQA + uptraining改动连续、工程生态成熟、质量与成本可调。
极端受限于 decode 带宽MQAKV 最小，但需要验证长上下文和多任务质量。
追求大模型长上下文和高并发MLA以 latent 形式存储历史，换取更低 cache 和通信开销。
最后一个判断：不要只比较“参数量”或“head 数”。应同时测量 KV cache bytes/token、decode 阶段实际 HBM 读流量、batch 增大后的吞吐、长上下文质量，以及 kernel 是否真的利用了共享/压缩布局。
MHA 先把表示能力拆成多个独立视角；MQA 发现推理时可以让这些视角共享历史；GQA 把全共享放松成可调分组；MLA 则进一步追问“为什么一定要缓存展开后的 K/V”。这条演变线的核心不是缩写越来越多，而是优化对象从 head 数、共享拓扑，推进到了历史状态的表示方式。理解这一点，才能在新模型出现时判断它究竟是在减少计算、减少存储，还是只把成本换到了另一个 kernel。
