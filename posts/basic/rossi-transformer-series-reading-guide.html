二、基础结构：先把 Transformer 拆开

这一段回答“Transformer 由什么组成、一个 token 如何进入模型、一个 block 如何完成计算”。第一次学习建议按顺序阅读 1 到 15，不要先跳到 KV Cache 或 MLA。

  1. （1）注意力机制从 Attention 的核心问题开始，是整个系列的入口。
  2. （2）总体架构把 Transformer 的整体模块和数据流串起来。
  3. （3）数据处理从原始文本到模型输入，补齐模型之外的数据入口。
  4. （4）编码器 & 解码器理解 encoder、decoder 及其差异。
  5. （5）训练 & 推理区分 teacher forcing、并行训练与自回归生成。
  6. （6）token理解文本如何被切分成模型真正处理的离散单位。
  7. （7）embedding从 token id 进入连续向量空间。
  8. （8）位置编码解释没有循环结构的 Transformer 如何感知顺序。
  9. （9）位置编码分类横向比较不同位置表示方法及其设计取舍。
  10. （10）自注意力聚焦 self-attention 的计算过程。
  11. （11）掩码理解 causal mask 等约束如何改变可见性。
  12. （12）多头自注意力进入 MHA，理解多个子空间并行建模的原因。
  13. （13）FFN补齐 Transformer block 中 attention 之外的主要计算。
  14. （14）残差网络和归一化理解深层训练稳定性和 block 连接方式。
  15. （15）采样和输出从 logits 走到生成 token，连接模型与解码策略。

三、效率账本：资源、位置与 KV Cache

读完基础结构后，第二条主线是“为什么模型能运行，但长文本和高并发会变贵”。第 16 到 29 篇集中处理显存、带宽、上下文长度、KV Cache 和专家模型。

  1. （16）资源占用建立参数、激活、显存和计算量的成本意识。
  2. （17）RoPE深入当前大模型常用的旋转位置编码。
  3. （18）FlashAttention从 IO 和显存访问角度理解 attention 加速。
  4. （19）FlashAttention V2 及升级版本继续追踪 attention kernel 的并行化和版本演进。
  5. （20）KV Cache理解自回归 decode 为什么需要缓存历史 K/V。
  6. （21）MoE进入稀疏专家模型，区分总参数量和每 token 激活参数量。
  7. （22）LoRA理解参数高效微调如何用低秩更新降低训练成本。
  8. （23）长度外推讨论训练上下文长度与推理上下文长度之间的鸿沟。
  9. （24）KV Cache 优化从基础缓存继续进入 KV Cache 的工程优化。
  10. （25）KV Cache 优化之处理长文本序列针对长上下文场景分析缓存压力。
  11. （26）KV Cache 优化：分离 or 合并从存储组织角度比较不同缓存布局。
  12. （27）MQA & GQA理解减少 KV head 如何降低缓存和 decode 带宽。
  13. （28）DeepSeek MLA从共享 head 推进到 latent KV 压缩。
  14. （29）DeepSeek MoE进一步理解 DeepSeek 路线中的稀疏专家架构。

四、推理加速：从一次生成到一次生成多个 token

第 30 到 33 篇围绕 speculative decoding 及其变体展开。它们共同面对一个问题：目标模型质量高但单步生成慢，能否用额外结构提出多个候选，再让目标模型并行验证。

  1. （30）投机解码建立 draft-and-verify 的总框架。
  2. （31）Medusa了解多头草稿结构如何并行提出未来 token。
  3. （32）Lookahead Decoding从前瞻式候选生成理解另一条加速路径。
  4. （33）DeepSeek MTP理解多 token 预测如何接入大模型训练和推理。

五、量化：把模型放进更现实的硬件预算

最后三篇集中讨论量化。建议先读第 16 篇资源占用，再读这里的基础和方案，否则容易只看到 bit 数变化，却忽略误差、校准、权重和激活的区别。

  1. （34）量化基础建立量化的基本概念和问题边界。
  2. （35）大模型量化基础把通用量化概念映射到 LLM 权重和激活。
  3. （36）大模型量化方案从基础走向具体的大模型量化路线和方案比较。

六、怎么读这 36 篇

你的目标建议路线读完应获得的判断力
第一次系统学 Transformer1 → 15能说清一个 Transformer block 的数据流。
分析推理显存和吞吐16 → 20 → 24 → 29能把上下文长度、KV head、带宽和缓存联系起来。
理解当前大模型架构17 → 21 → 27 → 28 → 29能区分位置编码、稀疏专家和注意力缓存的不同问题。
研究生成加速15 → 20 → 30 → 33能理解候选生成、目标验证和多 token 预测的关系。
做模型部署与压缩16 → 18 → 19 → 24 → 34 → 36能同时看计算、IO、缓存和量化误差，而不是只看参数量。
阅读时的一个原则：不要把编号顺序当成唯一学习顺序。基础篇适合线性阅读；进入工程阶段后，应围绕问题跳读。例如你在排查 decode 性能，最短路径通常是 16 → 20 → 24 → 27/28，而不是重新从第 1 篇开始。
