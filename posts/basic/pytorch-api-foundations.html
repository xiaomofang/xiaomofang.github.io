PyTorch 基础 API：从 Tensor 到大模型训练与推理

PyTorch 不必从一张 API 清单开始学。真正贯穿数据、模型和硬件的主线只有一句话：Tensor 带着形状、dtype、device 和梯度状态流过计算图。本文沿着这条线，把最常见的写法整理成一张可以迁移到 CNN、Transformer 和 Hugging Face 的基础地图。

先记一个排错顺序：看到 PyTorch 报错时，先看 shape，再看 dtype，最后看 device；如果数值不对，再检查 train/eval 和梯度上下文。

一、Tensor 是什么：数据和元数据的组合

Tensor 可以理解为带有统一数据类型的多维数组，但它比普通数组多了三个决定行为的属性：shape 描述每一维大小，dtype 描述元素精度，device 描述数据位于 CPU、CUDA 还是其他设备。大模型中的 token、hidden states、logits 和 KV cache，本质上都是 Tensor。

import torch

x = torch.tensor([[1, 2], [3, 4]], dtype=torch.float32)
print(x.shape, x.dtype, x.device, x.ndim, x.numel())
a = torch.zeros(2, 3)
b = torch.randn(2, 3)
ids = torch.arange(0, 8, dtype=torch.long)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
x = x.to(device=device, dtype=torch.float16)

蓝色定义层遇到 mat1 and mat2 shapes cannot be multiplied，不要先改代码，先把每个 Tensor 的 shape 打出来。

1.1 形状变换不等于数据变换

reshape、view、unsqueeze、squeeze 和 permute 常常连续出现。它们改变的是观察方式或维度顺序，不一定改变元素本身。Transformer 里把输入从 [batch, seq, hidden] 拆成多头，关键就是这些操作。

x = torch.randn(2, 3, 4)       # [batch, seq, hidden]
y = x.reshape(6, 4)
z = x.unsqueeze(1)              # [2, 1, 3, 4]
p = x.permute(0, 2, 1)          # [2, 4, 3]
q = torch.randn(2, 8, 16)
k = torch.randn(2, 8, 16)
scores = q @ k.transpose(-2, -1) # [2, 8, 8]
注意：transpose/permute 可能产生非 contiguous Tensor。需要时使用 contiguous()，或优先使用更灵活的 reshape()。

二、Autograd：为什么 loss.backward() 能工作

当 Tensor 参与计算且 requires_grad=True 时，PyTorch 会记录由算子组成的动态计算图。调用 backward()，框架从 loss 沿图反向应用链式法则，把结果累积到叶子 Tensor 的 .grad 中。

\[y=x^2+3x,\qquad \frac{\partial y}{\partial x}=2x+3\]
x = torch.tensor(2.0, requires_grad=True)
y = x * x + 3 * x
y.backward()
print(x.grad)  # tensor(7.)

features = model(input_ids).last_hidden_state.detach()
with torch.inference_mode():
    logits = model(input_ids)

橙色直觉层backward() 不会自动清空上一次梯度，所以训练循环必须在下一次反传前调用 optimizer.zero_grad()。梯度累积正是利用了这一点。

三、nn.Module：把参数、前向和模式组织起来

nn.Module 不只是一个函数容器。赋给它的 nn.Parameter 会被 model.parameters() 找到，子模块会随父模块一起移动设备、保存 checkpoint，并受到 train()/eval() 模式切换影响。

import torch.nn as nn

class TinyMLP(nn.Module):
    def __init__(self, hidden=768, classes=10):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(hidden, 1024), nn.GELU(),
            nn.LayerNorm(1024), nn.Linear(1024, classes)
        )

    def forward(self, x):
        return self.net(x)

model = TinyMLP().to(device)
目标典型 API注意点
词 id → 向量nn.Embedding[B,T] → [B,T,H]
分类 / LM lossnn.CrossEntropyLoss输入 logits，不要先 Softmax
训练态 / 推理态train() / eval()影响 Dropout、BatchNorm

四、训练循环：五步形成闭环

最小训练循环可以压缩为：取 batch、前向、算 loss、反向、更新参数。zero_grad 清理旧梯度，backward 产生新梯度，step 才根据梯度更新参数。

import torch.optim as optim

criterion = nn.CrossEntropyLoss()
optimizer = optim.AdamW(model.parameters(), lr=2e-5, weight_decay=0.01)
model.train()
for batch in dataloader:
    inputs = batch["input_ids"].to(device)
    labels = batch["labels"].to(device)
    optimizer.zero_grad(set_to_none=True)
    logits = model(inputs)
    loss = criterion(logits, labels)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()

紫色落地层优化器只持有参数引用和状态，不理解模型结构。因此要先构造 model，再把 model.parameters() 传给 optimizer。

Dataset 定义单条样本，DataLoader 负责 batch、shuffle 和 worker。数据处理逻辑越清楚，越容易排查 padding、label shift 和吞吐问题。

五、设备、dtype 与混合精度

把模型搬到 GPU 不等于把输入也搬过去；参与同一次算子的 Tensor 通常必须位于兼容的 device。工程上建议把 device 作为入口变量，而不是到处直接写 .cuda()。

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = model.to(device)
batch = {k: v.to(device, non_blocking=True) for k, v in batch.items()}
with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
    outputs = model(**batch)
    loss = outputs.loss

autocast 让适合低精度的算子使用低精度，同时保留敏感计算的精度。BF16 通常不需要 loss scaling；FP16 在部分环境中需要 GradScaler。实际速度还取决于 GPU、算子实现和输入 shape。

六、Transformer 与大模型推理

Attention 的核心是三步：QKᵀ 得到 token 间分数，除以 sqrt(d) 做尺度归一化，Softmax 后与 V 加权求和。PyTorch 2.x 可以用 fused API，避免手写版本产生多余中间 Tensor。

import torch.nn.functional as F

# q, k, v: [batch, heads, seq, head_dim]
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)

# 手写等价结构，便于理解
scores = q @ k.transpose(-2, -1) / (q.size(-1) ** 0.5)
weights = torch.softmax(scores, dim=-1)
out = weights @ v

推理时要同时做两件事：model.eval() 关闭训练态行为，torch.inference_mode() 关闭 autograd 的额外记录。前者是模型状态，后者是执行上下文，二者不是一回事。

model.eval()
with torch.inference_mode():
    inputs = tokenizer(prompt, return_tensors="pt").to(device)
    outputs = model.generate(**inputs, max_new_tokens=128,
                             do_sample=True, temperature=0.7, top_p=0.9)
text = tokenizer.decode(outputs[0], skip_special_tokens=True)
生成参数的边界：max_new_tokens 控制长度，temperature/top_p/top_k 控制采样。它们改变的是如何从 logits 选 token，不是模型本身的知识。

model.load_state_dict(torch.load("model.pt", map_location=device))
tokenizer.save_pretrained("./checkpoint")
model.save_pretrained("./checkpoint")

loss 不下降label、lr、梯度标签错位或参数未更新

学 PyTorch 的最短路径不是把函数背完，而是追踪一个 Tensor 的旅程：它从哪里创建，形状如何变化，在哪个 device 上，是否需要梯度，最后被哪个 loss 或生成策略消费。掌握这条主线，API 名称会从零散记忆变成可推导的工具箱。
