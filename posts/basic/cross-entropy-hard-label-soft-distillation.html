交叉熵、硬标签与软蒸馏：一份词表分布到底怎么算损失

读 EAGLE-3 时最容易卡的一句是：\(l_{\text{token}}=\mathrm{CE}(p,\hat{p})\)。 本文先用色图把「词表分布 / 硬标签 / 软蒸馏」算清楚，再借苏剑林 《除了交叉熵，LM Loss还有什么选择？》 回答更硬的一问：为什么语言模型几乎总是 Softmax + 交叉熵，而不是随便换个分类损失？

一、先看一次预测长什么样

假设前缀是「I love」，词表先缩成玩具版 {cats, dogs, to, eat, pizza}（真实 LLM 词表可以到十万级，算法一样）。 模型对「下一个词」输出 logits，再 softmax，得到 \(\hat{p}\)（下文也记作 \(q\)）：

\[ q(v)=\hat{p}(v)=\frac{e^{z_v}}{\sum_{u}e^{z_u}},\qquad \sum_v q(v)=1 \]
和「5 步拼起来」无关。 上图永远是某一个位置、某一轮预测的 \(q\)。 EAGLE-3 的 TTT 若模拟 5 步，就是做 5 轮这样的预测，各自算 CE 再相加——不是把 5 个位置的概率平均成一张图。

二、为什么 LM 几乎「只能」用交叉熵

常规图像分类：一张图通常对应一个正确答案。语言模型不同——「白切」后面可以是鸡、鸭、狗、羊…… 要建模的是完整条件分布，而不是只报一个 top-1。 但训练时语料又是零散采样进来的：这次见到「白切鸡」，下次见到「白切鸭」，你事先拿不到完整频率表。

苏神指出：这就要求损失对目标分布 \(p\) 线性，才能写成「对采样到的那个 token 算分再求期望」：

\[ L(p,q)=\sum_i p_i\,S(q,i)=\mathbb{E}_{i\sim p}\bigl[S(q,i)\bigr] \quad\text{且}\quad p=\arg\min_{q}\,L(p,q) \]

这就是恰当评分规则（Proper Scoring Rules）族。 Total Variation 之类看似自然的距离，往往没法在「只看见一个采样 token、又不知道 \(p_i\)」时稳定估计，因而不适合直接当 LM Loss。

唯一性（很强的一句）。 若进一步要求评分 \(S(q,i)\) 只依赖真类概率 \(q_i\)（不显式依赖其它类别的概率）， 那么在恰当评分框架下，本质上只剩下对数评分：\(S(q,i)=-\log q_i\)，也就是交叉熵。 这解释了「理所当然」背后的结构必然性，而不只是习惯。 详见 苏剑林 · 除了交叉熵，LM Loss还有什么选择？。

于是硬标签训练里你每天写的

\[ L=-\log q_y \]

并不是随便挑的分类损失，而是：在「只能看见一个采样标签 \(y\sim p\)、又希望学到整份分布」的约束下，几乎被迫选中的那一个。

三、硬标签：只问「真词概率有多高」

语料给出一个 token（如 cats），相当于从未知 \(p\) 抽到了 \(y=\text{cats}\)。 硬标签把这一次采样当成 one-hot，损失就是对数评分：

\[ y=\mathbf{1}_{\text{cats}},\qquad \mathrm{CE}(y,q)=-\log q(\text{cats}) \]

上图 \(q(\text{cats})=0.45\)，则 \(\mathrm{CE}=-\ln 0.45\approx 0.799\)。 其它词的柱子不直接进公式（只通过 softmax 分母间接影响）。

若 \(q(\text{cats})=0.90\)，则 \(-\ln 0.90\approx 0.105\)；若只有 \(0.05\)，则 \(-\ln 0.05\approx 3.00\)。 这是连续、可反传的惩罚，不是对错 0/1。

四、软蒸馏：手里已有整份 \(p\) 时

若目标模型能直接给出同位置整份教师分布 \(p\)（EAGLE / 蒸馏常见），就不必只靠「一次采样的 one-hot」， 可以直接写期望形式——这与上一节是同一条评分规则，只是 \(p\) 从「隐含、靠采样逼近」变成「显式给定」：

\[ \mathrm{CE}(p,q)=-\sum_v p(v)\log q(v)=\mathbb{E}_{v\sim p}\bigl[-\log q(v)\bigr] \]

沿用 EAGLE 玩具设定，设教师近似为 cats 0.52、dogs 0.19、to 0.09、eat 0.07、pizza 0.05：

硬标签 软蒸馏
\(p\) 从哪来 语料一次采样 → one-hot 教师模型整份分布（可带温度）
公式 \(-\log q(y)\) \(-\sum_v p(v)\log q(v)\)
关系 对未知 \(p\) 的蒙特卡洛估计 同一 \(L(p,q)\) 的显式期望
常见场景 预训练 / SFT 知识蒸馏、EAGLE 类 token 对齐

实务上通常二选一（按训练脚本配置），不是把硬 CE 与软 CE 无脑叠成两项主损失。 数值上硬/软算出来的标量不可直接比大小论优劣——目标不同。

五、Softmax + CE：为什么梯度这么「干净」

模型实际输出的是无界 logits \(z\)，再经 Softmax 得到 \(q\)。 在 Softmax 下，对数评分对 \(z\) 的梯度是：

\[ \nabla_z\bigl(-\log q_i\bigr)=q-e_i \]

这也解释了工程上的标配：交叉熵的最优配套激活几乎就是 Softmax（Fenchel–Young / 凸共轭视角下，要求 \(\nabla_z S=q-e_i\) 时反推出 Softmax）。 换损失往往还要换激活（如 Sparsemax / Entmax），牵一发而动全身——所以预训练默认仍是 Softmax+CE。

信息论写法：\(\mathrm{CE}(p,q)=H(p)+D_{\mathrm{KL}}(p\|q)\)。固定 \(p\) 时最小化 CE ≡ 最小化 KL。 硬标签时 \(H(p)=0\)，CE 与 KL 数值重合为 \(-\log q_y\)。

六、落到 PyTorch：别把概率和 logits 弄混

torch.nn.CrossEntropyLoss 默认：

  • input：未归一化 logits（内部 log-softmax），形状 (N, C)
  • target：类别下标 (N,)（硬标签），不是 one-hot
import torch
import torch.nn.functional as F

logits = torch.tensor([[2.0, 1.2, 0.5, 0.1, -0.3]])
hard = F.cross_entropy(logits, torch.tensor([0]))  # 真类 = cats

p_teacher = torch.tensor([[0.52, 0.19, 0.09, 0.07, 0.05]])
log_q = F.log_softmax(logits, dim=-1)
soft = -(p_teacher * log_q).sum(dim=-1).mean()  # 软蒸馏 CE
实现提示。 硬标签用 CrossEntropyLoss；软标签手写 \(-\sum p\log q\) 或 kl_div(log_softmax(logits), p)。 不要对已 softmax 的概率再丢进默认 CrossEntropyLoss。

七、接到 EAGLE-3：TTT 每步一份 CE

三句话收束：一次预测一份 \(q\)；硬标签是对未知 \(p\) 的采样版对数评分，软蒸馏是同一规则的显式期望； Softmax+CE 的梯度 \(q-e_i\) 又干净又凸，所以几乎总是标配——想换损失，先想清楚采样线性与配套激活。
