交叉熵是什么：从信息量算到硬标签、软蒸馏

交叉熵（Cross Entropy，常写成 CE）不是「对了记 1、错了记 0」，也不是两根向量的欧氏距离。 它量的是：用你猜的那份概率，去编码真实世界里实际发生的事，平均要花多少nats。 本文先把这个定义算清楚，再谈硬标签、软蒸馏，最后才接到语言模型和 EAGLE。

一、交叉熵从哪来

先忘掉神经网络。只问一件事：一件事发生了，它有多「意外」？

越稀有的事，说出来越费信息。信息论把「意外程度」写成

\[ I(x)=-\log p(x) \]

概率 \(0.5\) 的事，\(I=-\ln 0.5\approx 0.69\)；概率 \(0.05\) 的事，\(I\approx 3.00\)。 模型训练里常用自然对数，单位是 nat（用 \(\log_2\) 则是 bit，差一个常数倍，不影响谁大谁小）。

若世界本身按分布 \(p\) 出牌，平均意外程度就是熵：

\[ H(p)=\mathbb{E}_{x\sim p}\bigl[-\log p(x)\bigr]=-\sum_x p(x)\log p(x) \]

熵只取决于真实世界 \(p\)，和模型无关。它是「用完美码本编码这件事，平均最少要花多少」。

模型给不出真 \(p\)，只能给一份猜测 \(q\)。你仍然按真实世界的频率遇到各个 \(x\)， 但编码时用的是自己的 \(-\log q(x)\)。平均花销就是交叉熵：

\[ \mathrm{CE}(p,q)=H(p,q)=\mathbb{E}_{x\sim p}\bigl[-\log q(x)\bigr]=-\sum_x p(x)\log q(x) \]

「交叉」两个字：外层权重来自真分布 \(p\)，对数里却是你的猜测 \(q\)。两条分布交错在同一条求和里。

多花的那一截，正好是 KL 散度：

\[ \mathrm{CE}(p,q)=H(p)+D_{\mathrm{KL}}(p\|q) \]

\(H(p)\) 对固定数据是常数，训练时最小化 CE，等价于让 \(q\) 去贴 \(p\)（最小化 KL）。 \(q=p\) 时 KL 为零，交叉熵降到下界——就是熵本身。\(q\) 猜偏了，CE 一定比 \(H(p)\) 大。

二、怎么算：先给一个能手算的例子

词表先缩成五个词：{cats, dogs, to, eat, pizza}。 假设真实分布 \(p\)（或教师模型给出的软标签）是：

\[ p = (0.52,\ 0.19,\ 0.09,\ 0.07,\ 0.05) \]

模型先输出五个分数（logits），再 softmax 压成概率 \(q\)。softmax 只做一件事：把任意实数变成「和为 1、且每项为正」的分布：

\[ q(v)=\frac{e^{z_v}}{\sum_u e^{z_u}},\qquad \sum_v q(v)=1 \]

设模型此刻的预测是 \(q=(0.45,\ 0.25,\ 0.15,\ 0.10,\ 0.05)\)。代入定义：

\[ \begin{aligned} \mathrm{CE}(p,q) &= -(0.52\ln 0.45 + 0.19\ln 0.25 + 0.09\ln 0.15 + 0.07\ln 0.10 + 0.05\ln 0.05)\\ &\approx 1.41 \end{aligned} \]

每项都是「这个词有多常发生」乘「模型觉得它有多意外」。真词概率被模型压得很低时，\(-\log q\) 会很大，这一项就把总损失拉高。

三、硬标签：语料只告诉你「这次出现的是谁」

预训练、SFT 里，一条样本通常只有一个真词，例如这次下一词就是 cats。 这相当于把未知的真实分布，用一次采样近似成 one-hot：

\[ p = (1,0,0,0,0) \]

代回交叉熵定义，求和只剩一项：

\[ \mathrm{CE}(p,q)=-\log q(\text{cats}) \]

上图 \(q(\text{cats})=0.45\)，则 \(\mathrm{CE}=-\ln 0.45\approx 0.799\)。 dogs、to 那些柱子不直接出现在这一行公式里；它们只通过 softmax 的分母，把真词概率分走。 真词概率若被抬到 \(0.90\)，损失变成 \(-\ln 0.90\approx 0.105\)；若只剩 \(0.05\)，则约 \(3.00\)。 这是连续、可反传的惩罚，不是 0/1 记分。

四、软蒸馏：手里已经有整份 \(p\)

知识蒸馏、EAGLE 对齐目标模型时，教师可以直接给出同位置的整份词表分布，不必再压成 one-hot。 公式仍是第一节那个定义，只是 \(p\) 从「一次采样」变成「显式的一座山」：

\[ \mathrm{CE}(p,q)=-\sum_v p(v)\log q(v) \]
硬标签 软蒸馏
\(p\) 从哪来 语料一次采样 → one-hot 教师模型整份分布（可带温度）
公式 \(-\log q(y)\) \(-\sum_v p(v)\log q(v)\)
关系 对未知 \(p\) 的蒙特卡洛估计 同一条 CE 的显式期望
常见场景 预训练 / SFT 知识蒸馏、EAGLE 类 token 对齐

二者是同一条交叉熵，不是两种无关的损失。实务上通常按任务二选一，不必把硬 CE 和软 CE 无脑相加。 两个算出来的数字也不可直接比大小——\(p\) 不同，下界 \(H(p)\) 就不同。

五、为什么训练几乎总用 Softmax + CE

语言模型看起来像「逐 token 分类」，但语言是一对多的：「白切」后面可以是鸡、鸭、狗、羊。 要学的是整份条件分布，而语料又只零散地送来一个个采样。

苏剑林在 《除了交叉熵，LM Loss还有什么选择？》 里把这件事说死了：损失必须对 \(p\) 线性，才能写成「对采样到的那个 token 打分，再求期望」。 这类损失叫恰当评分规则。若再要求打分只依赖真类概率 \(q_y\)，本质上只剩下 \(-\log q_y\)，也就是交叉熵。

模型实际输出的是无界 logits \(z\)。配上 Softmax 之后，硬标签 CE 对 \(z\) 的梯度特别干净：

\[ \nabla_z\bigl(-\log q_i\bigr)=q-e_i \]

这也是 Softmax 和 CE 几乎总成对出现的原因：要梯度保持 \(q-e_i\) 这么干净，反推出来的激活就是 Softmax。 换损失往往还得换激活，所以预训练默认仍是这一套。

六、落到 PyTorch

torch.nn.CrossEntropyLoss 默认吃的是 logits + 类别下标，内部自己做 log-softmax，对应硬标签 \(-\log q_y\)： 

import torch
import torch.nn.functional as F

logits = torch.tensor([[2.0, 1.2, 0.5, 0.1, -0.3]])
hard = F.cross_entropy(logits, torch.tensor([0]))  # 真类 = cats

p_teacher = torch.tensor([[0.52, 0.19, 0.09, 0.07, 0.05]])
log_q = F.log_softmax(logits, dim=-1)
soft = -(p_teacher * log_q).sum(dim=-1).mean()  # 软蒸馏：显式 CE(p, q)
别混。 已经 softmax 过的概率，不要再丢进默认 CrossEntropyLoss。 软标签用手写 \(-\sum p\log q\)，或 kl_div(log_softmax(logits), p)（注意它吃的是 log-prob）。

七、再回到 EAGLE：TTT 只是多份 CE 相加

EAGLE-3 去掉特征回归之后，token 损失就是上面这种 CE（硬或软，看训练脚本）。 Training-Time Test 模拟约 5 步，不是把 5 个位置的概率拼成一条再算一次，而是： 每一步各自产出一份 \(q\)，各自算一次 CE，再求和。

交叉熵先是信息论里的「用错码本要多花多少」；落到分类上，硬标签是一次采样版，软蒸馏是整座山对齐版； Softmax 让梯度变成 \(q-e_i\)，所以训练几乎总用这一对。EAGLE 的 token 损失，只是把同一件事做了多步。
